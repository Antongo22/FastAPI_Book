Глава 3: HTTP Requests

Асинхронные запросы к внешним API через httpx и сервисный слой.

Порт: 8003 Swagger: http://localhost:8003/docs Результат: После главы вы понимаете, как не блокировать event loop и как отделять endpoint от внешней интеграции.

Как пользоваться этой главой

Здесь ваше приложение впервые общается с чужим API. Это частая задача: забрать данные из внешнего сервиса, проверить ошибку и вернуть клиенту понятный результат.

Держите в голове два запроса: клиент вызывает ваш FastAPI endpoint, а внутри endpoint-а ваш код вызывает JSONPlaceholder через httpx.

Если внешний сервис недоступен, это не должно превращаться в непонятное падение. Поэтому в этой главе важны timeout, обработка HTTP-ошибок и сервисный слой.

Если вы только начинаете: не перепрыгивайте сразу к ответу. Сначала запустите пример, затем откройте код рядом с этой страницей и проговаривайте каждую строку обычными словами.

Что разбираем в этой главе

  • httpx.AsyncClient - асинхронный HTTP-клиент для outbound-запросов.
  • Timeout - обязательная защита от зависания внешнего сервиса.
  • Service layer - класс, который скрывает детали внешнего API от контроллера.
  • raise_for_status - перевод HTTP 4xx/5xx во внутреннее исключение.
  • Error mapping - преобразование ошибок внешнего API в понятный ответ вашего API.

Как проходит запрос

  1. Клиент вызывает ваш endpoint, например /api/http-client/post/1.
  2. Endpoint получает ExternalApiService через dependency.
  3. Сервис открывает httpx.AsyncClient с base URL и timeout.
  4. Внешний ответ проверяется через raise_for_status().
  5. JSON внешнего сервиса возвращается клиенту вашего API.
  6. При ошибке endpoint возвращает HTTP 502 или код внешнего ответа.

Если совсем по-простому

Здесь приложение само становится клиентом другого API. Пользователь обращается к нам, а мы внутри делаем запрос на JSONPlaceholder.

Важно не путать два направления: входящий запрос приходит в FastAPI, исходящий запрос отправляет httpx.

Асинхронность нужна, чтобы сервер не простаивал, пока ждёт ответ внешнего сайта.

Построчный разбор

class ExternalApiService:
Создаём класс-сервис. Он отвечает за общение с внешним API, чтобы endpoint был коротким.
async def get_post(...)
Асинхронный метод. Его можно вызывать с await.
post_id: int
Ожидаем целое число. Например, 1, 2, 10.
-> dict
Подсказка: метод вернёт словарь Python.
async with httpx.AsyncClient(...)
Открываем HTTP-клиент на время блока. После блока он корректно закрывается.
base_url=self.base_url
Общий адрес внешнего сервиса задаётся один раз, дальше можно писать только путь.
timeout=10.0
Если внешний сервис зависнет, мы не будем ждать вечно.
await client.get(...)
Отправляем GET-запрос и ждём ответ.
response.raise_for_status()
Если внешний API вернул ошибку 404/500, превращаем её в исключение.
return response.json()
Берём JSON из ответа и возвращаем его как Python-объект.

Что здесь важно

  • Клиент создаётся внутри async with, поэтому соединения корректно закрываются.
  • В больших приложениях клиент можно держать дольше через lifespan, но для учебного примера локальный context manager проще.
  • Endpoint не знает URL внешнего API: это ответственность сервиса.

Типичные ошибки новичков

  • Забыть await перед асинхронным запросом.
  • Создавать запросы без timeout и зависнуть на плохом внешнем сервисе.
  • Смешать логику внешнего API прямо с endpoint-ом, из-за чего код станет трудно тестировать.

Контрольные вопросы

  2. Зачем нужен timeout при вызове внешнего сервиса?
  3. Что делает raise_for_status()?
  4. Почему внешний API лучше спрятать в отдельный service class?

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что добавляем

Добавляем новый метод во внешний сервис и отдельный endpoint. Endpoint остаётся тонким: он только вызывает сервис и обрабатывает ошибку.

  • Добавить метод get_post_comments в ExternalApiService.
  • Добавить route GET /api/http-client/post/{post_id}/comments.
  • Использовать тот же map_http_error, что и в остальных методах.

2. Полный код метода сервиса и endpoint-а

{% raw %}class ExternalApiService:
    def __init__(self, base_url: str = JSONPLACEHOLDER):
        self.base_url = base_url

    async def get_post_comments(self, post_id: int) -> list[dict]:
        async with httpx.AsyncClient(base_url=self.base_url, timeout=10.0) as client:
            response = await client.get(f"/posts/{post_id}/comments")
            response.raise_for_status()

@app.get("/api/http-client/post/{post_id}/comments")

3. Как проверить

GET /api/http-client/post/1/commentsВернётся список комментариев к посту 1.
GET /api/http-client/post/999999/commentsВнешний API может вернуть пустой список или ошибку, это зависит от сервиса.

Короткая версия решения

Разбор решения

  • Метод должен жить в сервисе, чтобы endpoint оставался тонким.
  • Обработку httpx.HTTPError можно переиспользовать из существующих endpoint-ов.
