Глава 3: HTTP Requests

Асинхронные запросы к внешним API через httpx и сервисный слой.

Порт: 8003 Swagger: http://localhost:8003/docs Результат: После главы вы понимаете, как не блокировать event loop и как отделять endpoint от внешней интеграции.

Что разбираем в этой главе

  • httpx.AsyncClient - асинхронный HTTP-клиент для outbound-запросов.
  • Timeout - обязательная защита от зависания внешнего сервиса.
  • Service layer - класс, который скрывает детали внешнего API от контроллера.
  • raise_for_status - перевод HTTP 4xx/5xx во внутреннее исключение.
  • Error mapping - преобразование ошибок внешнего API в понятный ответ вашего API.

Как проходит запрос

  1. Клиент вызывает ваш endpoint, например /api/http-client/post/1.
  2. Endpoint получает ExternalApiService через dependency.
  3. Сервис открывает httpx.AsyncClient с base URL и timeout.
  4. Внешний ответ проверяется через raise_for_status().
  5. JSON внешнего сервиса возвращается клиенту вашего API.
  6. При ошибке endpoint возвращает HTTP 502 или код внешнего ответа.

Ключевой фрагмент

{% raw %}import httpx
from fastapi import Depends, FastAPI, HTTPException
from pydantic import BaseModel


JSONPLACEHOLDER = "https://jsonplaceholder.typicode.com"


app = FastAPI(
    title="Глава 3: HTTP Requests",
    description="httpx AsyncClient",
    version="1.0.0",
)


class CreatePostRequest(BaseModel):
    title: str
    body: str
    user_id: int


class ExternalApiService:
    def __init__(self, base_url: str = JSONPLACEHOLDER):
        self.base_url = base_url

    async def get_post(self, post_id: int) -> dict:
        async with httpx.AsyncClient(base_url=self.base_url, timeout=10.0) as client:
            response = await client.get(f"/posts/{post_id}")
            response.raise_for_status()
            return response.json()

    async def create_post(self, request: CreatePostRequest) -> dict:
        payload = {"title": request.title, "body": request.body, "userId": request.user_id}
        async with httpx.AsyncClient(base_url=self.base_url, timeout=10.0) as client:
            response = await client.post("/posts", json=payload)
            response.raise_for_status()
            return response.json()


def get_external_api_service() -> ExternalApiService:
    return ExternalApiService()


def map_http_error(error: httpx.HTTPError) -> HTTPException:
    status_code = 502
    if isinstance(error, httpx.HTTPStatusError):
        status_code = error.response.status_code
    return HTTPException(status_code=status_code, detail=str(error))


@app.get("/api/http-client/post/{post_id}")
async def get_post(post_id: int, service: ExternalApiService = Depends(get_external_api_service)):
    try:
        return await service.get_post(post_id)
    except httpx.HTTPError as error:
        raise map_http_error(error) from error{% endraw %}

Если совсем по-простому

Здесь приложение само становится клиентом другого API. Пользователь обращается к нам, а мы внутри делаем запрос на JSONPlaceholder.

Важно не путать два направления: входящий запрос приходит в FastAPI, исходящий запрос отправляет httpx.

Асинхронность нужна, чтобы сервер не простаивал, пока ждёт ответ внешнего сайта.

Что здесь важно

  • Клиент создаётся внутри async with, поэтому соединения корректно закрываются.
  • В больших приложениях клиент можно держать дольше через lifespan, но для учебного примера локальный context manager проще.
  • Endpoint не знает URL внешнего API: это ответственность сервиса.

Типичные ошибки новичков

  • Забыть await перед асинхронным запросом.
  • Создавать запросы без timeout и зависнуть на плохом внешнем сервисе.
  • Смешать логику внешнего API прямо с endpoint-ом, из-за чего код станет трудно тестировать.

Полное решение задачи

Это ответ именно к задаче из вкладки “Практика”. Здесь показано, что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что добавляем

Решение должно реально сходить в открытый внешний сервис JSONPlaceholder. Не создавайте локальный список комментариев и не возвращайте заранее написанный JSON: смысл задачи - потренироваться на стороннем HTTP API.

  • Публичный base URL уже есть в главе: JSONPLACEHOLDER = "https://jsonplaceholder.typicode.com".
  • Метод сервиса должен вызвать внешний путь /posts/{post_id}/comments через httpx.AsyncClient.
  • FastAPI endpoint должен остаться тонким: принять post_id, вызвать метод сервиса и обработать httpx.HTTPError.
  • Для ошибок используйте тот же map_http_error, что и в остальных endpoint-ах главы.

3. Как проверить

Внешний API напрямуюОткройте https://jsonplaceholder.typicode.com/posts/1/comments и убедитесь, что сторонний сервис возвращает JSON.
GET /api/http-client/post/1/commentsВаш endpoint возвращает список комментариев к посту 1 из JSONPlaceholder.
GET /api/http-client/post/999999/commentsВнешний API может вернуть пустой список или ошибку, это зависит от сервиса.

Полный разбор ответа

Ниже решение разобрано по частям: что стоит на своём месте, зачем это нужно и какие ошибки чаще всего появляются, если часть кода пропустить.

Зачем нужен service layer

Задача добавляет запрос к реальному внешнему API JSONPlaceholder. Endpoint не должен сам знать все детали HTTP-клиента, поэтому логика запроса лежит в ExternalApiService.

  • JSONPLACEHOLDER хранит базовый URL внешнего сервиса в одном месте.
  • ExternalApiService.__init__ принимает base_url, чтобы в тестах или будущем окружении можно было подменить внешний адрес.
  • Метод get_post_comments лежит внутри сервиса, потому что это такая же внешняя операция, как получение поста.
  • Endpoint остаётся тонким: он принимает post_id, получает сервис через dependency и возвращает результат сервиса.

Как работает httpx-код

  • async with httpx.AsyncClient(...) открывает HTTP-клиент на время запроса и корректно закрывает соединения после выхода из блока.
  • base_url=self.base_url позволяет писать короткий путь /posts/{post_id}/comments, а не полный URL каждый раз.
  • timeout=10.0 нужен, чтобы приложение не висело бесконечно, если внешний сервис тормозит.
  • await client.get(...) отправляет GET-запрос асинхронно. Пока внешний API отвечает, event loop может обслуживать другие запросы.
  • response.raise_for_status() превращает HTTP 4xx/5xx внешнего API в исключение, которое потом можно обработать единообразно.

Как endpoint связан с сервисом

  • post_id: int берётся из path-параметра /post/{post_id}/comments.
  • service: ExternalApiService = Depends(get_external_api_service) просит FastAPI создать или вернуть сервис.
  • return await service.get_post_comments(post_id) отдаёт клиенту JSON, полученный из внешнего API.
  • except httpx.HTTPError as error нужен, чтобы не показывать пользователю внутреннюю ошибку Python.
  • raise map_http_error(error) from error сохраняет общий формат обработки ошибок, уже принятый в главе.

Как отличить реальную интеграцию от заглушки

  • Сначала откройте https://jsonplaceholder.typicode.com/posts/1/comments напрямую. Вы должны увидеть список комментариев.
  • Потом откройте локальный endpoint /api/http-client/post/1/comments. Структура ответа должна быть похожей.
  • В коде не должно быть заранее написанного локального списка комментариев. Иначе задача не тренирует outbound HTTP.
  • Если внешний сервис вернёт ошибку, ваш endpoint должен пройти через map_http_error, а не падать с traceback.

Читаем HTTP-интеграцию сверху вниз

  • import httpx нужен, потому что исходящий HTTP-запрос делает не FastAPI, а клиентская библиотека httpx.
  • JSONPLACEHOLDER вынесен в константу, чтобы внешний адрес не был размазан по методам сервиса.
  • CreatePostRequest относится к другому endpoint-у главы, но остаётся в полном ответе, чтобы файл был целиком рабочим.
  • ExternalApiService собирает в одном месте все обращения к JSONPlaceholder.
  • get_external_api_service - dependency, которая отдаёт endpoint-ам готовый service object.
  • map_http_error стоит отдельно, потому что ошибку внешнего API надо превращать в ошибку вашего API единообразно.

Что происходит при запросе comments

  • Клиент вызывает локальный URL /api/http-client/post/1/comments, а не внешний JSONPlaceholder напрямую.
  • FastAPI берёт post_id=1 из path.
  • FastAPI вызывает get_external_api_service и передаёт результат в параметр service.
  • Endpoint вызывает await service.get_post_comments(post_id).
  • Сервис открывает httpx.AsyncClient с base_url=JSONPLACEHOLDER.
  • Сервис отправляет внешний запрос на /posts/1/comments.
  • Внешний JSON возвращается из сервиса в endpoint, а endpoint отдаёт его клиенту.

Зачем нужен try/except вокруг await

  • Внешний сервис может быть недоступен, вернуть 404, 500 или ответить слишком медленно.
  • Если не перехватить httpx.HTTPError, клиент вашего API увидит внутреннюю ошибку приложения.
  • except httpx.HTTPError as error ловит сетевые ошибки и ошибки status code после raise_for_status().
  • map_http_error(error) превращает техническую ошибку httpx в понятный HTTPException FastAPI.
  • from error сохраняет связь исключений для отладки, но клиенту наружу отдаётся аккуратный HTTP-ответ.

Короткое резюме решения

  • Метод должен жить в сервисе, чтобы endpoint оставался тонким.
  • Обработку httpx.HTTPError можно переиспользовать из существующих endpoint-ов.
