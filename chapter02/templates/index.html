Глава 2: Dependency Injection

Depends, dependency graph, кеширование зависимостей в рамках запроса и singleton-style сервисы.

Порт: 8002 Swagger: http://localhost:8002/docs Результат: После главы вы умеете выносить подготовку сервисов из endpoint-ов и понимать, когда объект создаётся один раз, а когда на каждый вызов.

Что разбираем в этой главе

  • Dependency - функция, результат которой FastAPI передаёт в endpoint.
  • Depends - декларация зависимости прямо в параметрах функции.
  • Request cache - одинаковая dependency по умолчанию вызывается один раз за запрос.
  • use_cache=False - способ получить transient-поведение.
  • Singleton-style - обычный модульный объект Python, который живёт всё время процесса.

Как проходит запрос

  1. Клиент вызывает GET /api/dependency-injection/lifetimes.
  2. FastAPI строит дерево зависимостей по параметрам endpoint-а.
  3. Scoped dependency вызывается один раз и переиспользуется для двух параметров.
  4. Singleton возвращает один и тот же объект из модуля.
  5. Transient dependency помечена use_cache=False, поэтому создаётся дважды.
  6. Endpoint возвращает идентификаторы объектов, чтобы поведение было видно в Swagger.

Endpoint-ы для проверки

Если совсем по-простому

Dependency Injection в FastAPI - это способ попросить фреймворк подготовить нужный объект за вас.

Вместо того чтобы внутри endpoint-а вручную создавать сервис, вы пишете Depends(...), а FastAPI вызывает нужную функцию сам.

Для новичка это можно представить так: endpoint говорит 'мне нужен сервис', FastAPI приносит его перед запуском функции.

Построчный разбор

def get_scoped_service()
Обычная функция Python. Её задача - создать и вернуть объект сервиса.
-> InstanceService
Подсказка типа. Она не создаёт объект сама, но помогает читать код и понимать, что функция возвращает.
return InstanceService(...)
Создаём новый объект и сразу возвращаем его тому, кто вызвал функцию.
@app.get(...)
Регистрируем GET endpoint. Браузер или Swagger может вызвать его обычным GET-запросом.
async def lifetimes(...)
Endpoint принимает не только данные запроса, но и зависимости.
Depends(get_scoped_service)
FastAPI вызовет get_scoped_service и подставит результат в параметр.
scoped1 и scoped2
Оба параметра используют одну dependency. FastAPI по умолчанию кеширует результат в рамках одного запроса.
use_cache=False
Отключаем кеш. Поэтому transient-сервис создаётся заново для каждого параметра.
shape(scoped1)
Вспомогательная функция превращает объект сервиса в простой словарь для JSON-ответа.

Что здесь важно

  • Одинаковый Depends(get_scoped_service) кешируется в рамках одного HTTP-запроса.
  • use_cache=False явно отключает кеш, поэтому transient получает разные id.
  • В реальном проекте dependency часто возвращает репозиторий, DB session, настройки или текущего пользователя.

Типичные ошибки новичков

  • Вызвать dependency самому: Depends(get_service()). Нужно передавать функцию без скобок: Depends(get_service).
  • Ожидать, что FastAPI создаст новый объект при каждом параметре, хотя кеширование включено.
  • Хранить изменяемое состояние в singleton без понимания, что оно общее для всех запросов.

Практическая задача

Создайте dependency get_request_id(), которая возвращает UUID запроса, и endpoint /api/dependency-injection/request-id.

Сначала выполните задачу самостоятельно, затем откройте вкладку “Ответы” и сравните не только код, но и причину такого решения.

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что создаём

Нужно добавить отдельную dependency, которая генерирует request id, и endpoint, который показывает этот id клиенту.

  • В файле chapter02/app/main.py уже импортирован uuid4.
  • Создаём функцию get_request_id рядом с другими dependency.
  • Создаём endpoint GET /api/dependency-injection/request-id.
  • Передаём dependency в endpoint через Depends, а не вызываем вручную.

2. Полный код новой dependency и endpoint-а

{% raw %}def get_request_id() -> str:
    return str(uuid4())


@app.get("/api/dependency-injection/request-id")
async def request_id(value: str = Depends(get_request_id)):
    return {
        "request_id": value,
        "explanation": "FastAPI вызвал get_request_id() и передал результат в endpoint.",
    }{% endraw %}

3. Как проверить

Вызовите endpoint два раза подряд. Значение должно меняться, потому что каждый HTTP-запрос получает свой request id.

GET /api/dependency-injection/request-idОтвет содержит поле request_id.
GET /api/dependency-injection/request-idПовторный запрос возвращает другой UUID.

Короткая версия решения

{% raw %}def get_request_id() -> str:
    return str(uuid4())


@app.get("/api/dependency-injection/request-id")
async def request_id(value: str = Depends(get_request_id)):
    return {"request_id": value}{% endraw %}

Разбор решения

  • Если один request id нужен в нескольких зависимостях, оставьте кеширование включённым.
  • Если нужен новый id на каждый вызов dependency, используйте use_cache=False.
