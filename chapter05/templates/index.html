Глава 5: Jinja2 UI

Серверные HTML-шаблоны, формы, Form-параметры и Pydantic-валидация вместо Razor Pages.

Порт: 8005 Swagger: http://localhost:8005/docs Результат: После главы вы понимаете, как FastAPI отдаёт HTML, принимает формы и показывает ошибки пользователю.

Что разбираем в этой главе

  • Jinja2Templates - подключение папки HTML-шаблонов.
  • TemplateResponse - ответ, который рендерит шаблон на сервере.
  • request - обязательный объект в context для Starlette templates.
  • Form - чтение данных из HTML-формы вместо JSON-body.
  • Pydantic validation - единая проверка формы перед сохранением или отправкой.

Как проходит запрос

  1. Пользователь открывает /contact, FastAPI рендерит HTML-форму.
  2. Браузер отправляет POST /contact с application/x-www-form-urlencoded.
  3. FastAPI передаёт поля в параметры Form.
  4. Pydantic-модель проверяет пустые строки и формат email.
  5. При ошибке тот же шаблон рендерится со status 400 и списком ошибок.
  6. При успехе страница показывает сообщение о принятой форме.

Endpoint-ы для проверки

GET /contactHTML-форма контакта.

Если совсем по-простому

До этого мы в основном возвращали JSON. Здесь FastAPI возвращает обычную HTML-страницу.

Jinja2 - это шаблонизатор: HTML-файл с местами, куда сервер подставляет данные.

Форма отправляет не JSON, а специальные form-поля. Поэтому используются параметры Form.

Построчный разбор

@app.post("/contact", response_class=HTMLResponse)
Этот endpoint принимает отправку формы и возвращает HTML, а не JSON.
include_in_schema=False
Прячем HTML endpoint из Swagger, потому что это страница для браузера, а не API для клиента.
request: Request
Объект запроса нужен Jinja2-шаблону.
name: str = Form("")
Берём поле name из HTML-формы. Если его нет, используем пустую строку.
email: str = Form("")
То же самое для email.
message: str = Form("")
То же самое для текста сообщения.
values = {...}
Складываем введённые данные в словарь, чтобы при ошибке вернуть их обратно на страницу.
ContactForm(**values)
Передаём словарь в Pydantic-модель. Две звёздочки означают 'развернуть словарь в именованные аргументы'.
ValidationError
Если Pydantic нашёл ошибку, мы ловим её и показываем рядом с полями формы.

Что здесь важно

  • HTML-форма и JSON API могут использовать одну Pydantic-модель, чтобы правила не расходились.
  • Ошибки формы лучше возвращать на ту же страницу, сохраняя введённые пользователем значения.
  • Для файлов и сложных форм понадобится python-multipart, он уже есть в requirements.

Типичные ошибки новичков

  • Забыть установить python-multipart, без него FastAPI не принимает формы.
  • Не передать request в шаблон.
  • При ошибке очистить форму, заставив пользователя вводить всё заново.

Практическая задача

Добавьте страницу регистрации с полями username, email, password и серверной проверкой, что пароль не короче 6 символов.

Сначала выполните задачу самостоятельно, затем откройте вкладку “Ответы” и сравните не только код, но и причину такого решения.

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что добавляем

Для полноценной страницы регистрации нужны три части: Pydantic-модель формы, GET-handler для показа страницы и POST-handler для обработки отправки.

  • Добавить модель RegistrationForm в chapter05/app/main.py.
  • Добавить GET /register и POST /register.
  • Создать шаблон chapter05/templates/register.html.

2. Полный код Python-части

{% raw %}class RegistrationForm(BaseModel):
    username: str
    email: str
    password: str

    @field_validator("username", "email", "password")
    @classmethod
    def not_empty(cls, value: str) -> str:
        if not value.strip():
            raise ValueError("Поле обязательно")
        return value.strip()

    @field_validator("email")
    @classmethod
    def email_has_at(cls, value: str) -> str:
        if "@" not in value:
            raise ValueError("Email должен содержать @")
        return value

    @field_validator("password")
    @classmethod
    def password_is_long_enough(cls, value: str) -> str:
        if len(value) < 6:
            raise ValueError("Пароль должен быть не короче 6 символов")
        return value

@app.post("/register", response_class=HTMLResponse, include_in_schema=False)
async def submit_register(
    request: Request,
    username: str = Form(""),
    email: str = Form(""),
    password: str = Form(""),
):
    values = {"username": username, "email": email, "password": password}
    try:
        RegistrationForm(**values)
    except ValidationError as error:
        errors = {str(item["loc"][0]): item["msg"] for item in error.errors()}
        return templates.TemplateResponse(
            request,
            "register.html",
            {"request": request, "errors": errors, "values": values, "registered": False},
            status_code=400,
        )
    return templates.TemplateResponse(
        request,
        "register.html",
        {"request": request, "errors": {}, "values": values, "registered": True},
    ){% endraw %}

Разбор решения

  • GET-handler должен показывать пустую форму, POST-handler - валидировать и возвращать тот же шаблон.
  • Не храните пароль в открытом виде: в auth-главах он будет хешироваться.
