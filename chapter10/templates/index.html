Глава 10: Socket.IO чат

Socket.IO events, sid, rooms, broadcast и direct messages.

Порт: 8010 Swagger: http://localhost:8010/docs Результат: После главы вы понимаете, как подключить Socket.IO к FastAPI и обмениваться real-time событиями.

Как пользоваться этой главой

Здесь используется Socket.IO: отдельная real-time технология с событиями, комнатами и готовой клиентской библиотекой.

Raw WebSocket endpoint в главе оставлен как низкоуровневый пример, а основной учебный сценарий показывает Socket.IO события.

Обратите внимание на договорённость между клиентом и сервером: какие события существуют, какие поля есть в payload и куда сервер делает emit.

Если вы только начинаете: не перепрыгивайте сразу к ответу. Сначала запустите пример, затем откройте код рядом с этой страницей и проговаривайте каждую строку обычными словами.

Что разбираем в этой главе

  • Socket.IO - real-time библиотека с событиями, комнатами и автоматическим протоколом поверх HTTP/WebSocket transport.
  • sid - server-side id конкретного Socket.IO-подключения.
  • event - именованное сообщение, например chat_message или join_room.
  • room - комната, куда можно добавить несколько подключений и отправлять события группе.
  • emit - отправка события одному клиенту, комнате или всем подключённым клиентам.

Как проходит запрос

  1. Клиент подключается через Socket.IO к http://localhost:8010 с path /socket.io.
  2. Сервер получает событие connect, запоминает sid и отправляет клиенту событие connected.
  3. Клиент отправляет событие set_name, чтобы сервер связал sid с именем пользователя.
  4. Клиент отправляет join_room, и сервер добавляет подключение в комнату.
  5. Клиент отправляет chat_message, а сервер делает emit всем или выбранной комнате.
  6. При disconnect сервер очищает локальные словари подключений и комнат.

Базовые Socket.IO события урока

{% raw %}sio = socketio.AsyncServer(async_mode="asgi", cors_allowed_origins="*")
fastapi_app = FastAPI(title="Глава 10: Socket.IO chat")
app = socketio.ASGIApp(
    sio,
    other_asgi_app=fastapi_app,
    socketio_path="socket.io",
)

socketio_clients: dict[str, str] = {}

@sio.event
async def connect(sid, environ, auth):
    socketio_clients[sid] = "anonymous"
    await sio.emit("connected", {"sid": sid}, to=sid)


@sio.event
async def set_name(sid, data):
    username = data.get("username") or "anonymous"
    socketio_clients[sid] = username
    await sio.emit("name_set", {"username": username}, to=sid)


@sio.event
async def direct_message(sid, data):
    target_sid = data.get("sid")
    payload = {
        "event": "direct_message",
        "from": socketio_clients.get(sid, "anonymous"),
        "message": data.get("message", ""),
    }
    if target_sid:
        await sio.emit("direct_message", payload, to=target_sid)


@sio.event
async def disconnect(sid):
    socketio_clients.pop(sid, None){% endraw %}

Если совсем по-простому

Socket.IO - это отдельная real-time технология, где общение строится вокруг событий: клиент отправляет событие, сервер обрабатывает его по имени.

Вместо ручного поля action у каждого действия есть своё имя: join_room, chat_message, direct_message.

Главная мысль: WebSocket может быть транспортом, а Socket.IO добавляет поверх него удобные события, комнаты и клиентскую библиотеку.

Построчный разбор

sio = socketio.AsyncServer(...)
Создаём Socket.IO server, который умеет принимать асинхронные события.
fastapi_app = FastAPI(...)
Создаём обычное FastAPI-приложение для HTTP endpoint-ов главы.
socketio.ASGIApp(...)
Объединяем Socket.IO server и FastAPI-приложение в одно ASGI-приложение.
socketio_path="socket.io"
Указываем путь Socket.IO внутри ASGI-приложения. В браузере этот путь обычно выглядит как /socket.io.
@sio.event
Декоратор регистрирует функцию как обработчик события. Имя функции становится именем события.
async def connect(sid, environ, auth)
Срабатывает при новом подключении клиента.
sid
Уникальный id подключения. Его выдаёт Socket.IO server.
data
Payload события. Обычно это обычный словарь с данными от клиента.
socketio_clients[sid] = "anonymous"
Сохраняем подключение с временным именем, пока пользователь не отправит своё имя.
async def set_name(...)
Обрабатываем событие, которое меняет имя пользователя в учебном словаре.
async def direct_message(...)
Обрабатываем событие личного сообщения.
target_sid = data.get("sid")
Берём id клиента, которому нужно отправить личное сообщение.
await sio.emit(..., to=target_sid)
Отправляем событие только выбранному клиенту.
async def disconnect(sid)
Срабатывает при отключении клиента и очищает учебное состояние.

Что здесь важно

  • Socket.IO работает событиями: клиент и сервер договариваются об именах событий и структуре payload.
  • Комнаты удобнее ручного хранения списков получателей: сервер вызывает enter_room и отправляет событие в room.
  • В этой главе также оставлен raw WebSocket endpoint, чтобы было видно, чем ручной протокол отличается от событий Socket.IO.

Типичные ошибки новичков

  • Подключать Socket.IO клиент к raw WebSocket endpoint-у /ws/chat. Socket.IO использует свой протокол и path /socket.io.
  • Путать имя события и поле внутри JSON. В Socket.IO событие называется отдельно, например chat_message.
  • Забыть удалить sid из учебных словарей при disconnect.

Полное решение задачи

Это ответ именно к задаче из вкладки “Практика”. Здесь показано, что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что меняем

Добавляем новое Socket.IO событие. Оно удаляет текущее подключение из комнаты и возвращает подтверждение только этому клиенту.

  • В файл chapter10/app/main.py добавить обработчик @sio.event.
  • Назвать функцию leave_room, чтобы имя функции совпало с именем события.
  • Взять имя комнаты из payload или использовать general.
  • Вызвать sio.leave_room и отправить событие left_room текущему клиенту.

2. Полный блок Socket.IO событий для комнат

{% raw %}@sio.event
async def join_room(sid, data):
    room = data.get("room", "general")
    await sio.enter_room(sid, room)
    socketio_rooms[room].add(sid)
    await sio.emit("joined_room", {"room": room}, to=sid)


@sio.event
async def leave_room(sid, data):
    room = data.get("room", "general")
    await sio.leave_room(sid, room)
    socketio_rooms[room].discard(sid)
    await sio.emit("left_room", {"room": room}, to=sid)


@sio.event
async def chat_message(sid, data):
    room = data.get("room")
    payload = {
        "event": "chat_message",
        "from": socketio_clients.get(sid, "anonymous"),
        "message": data.get("message", ""),
        "room": room,
    }
    if room:
        await sio.emit("chat_message", payload, room=room)
    else:
        await sio.emit("chat_message", payload){% endraw %}

3. Как проверить

Socket.IO join_roomОтправьте { room: "python" } и получите событие joined_room.
Socket.IO leave_roomОтправьте { room: "python" } и получите событие left_room.

Разбор решения

  • Метод leave_room убирает sid из внутренней комнаты Socket.IO.
  • Локальный словарь socketio_rooms нужен только для учебного endpoint-а /api/chat/info.
