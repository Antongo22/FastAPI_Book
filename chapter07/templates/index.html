Глава 7: Authentication и Authorization

Регистрация, вход, password hashing, JWT access token и protected endpoint.

Порт: 8007 Swagger: http://localhost:8007/docs Результат: После главы вы понимаете разницу между проверкой личности и проверкой прав доступа.

Что разбираем в этой главе

  • Authentication - подтверждаем, кто пользователь.
  • Authorization - решаем, разрешено ли пользователю действие.
  • Password hash - пароль нельзя хранить открытым текстом.
  • JWT - подписанный token с claims вроде sub, role и exp.
  • OAuth2PasswordBearer - dependency, которая читает Bearer token из заголовка Authorization.

Как проходит запрос

  1. Пользователь регистрируется через /api/auth/register.
  2. Пароль хешируется, а не сохраняется как есть.
  3. Сервер выпускает JWT с username, role и временем истечения.
  4. Клиент передаёт token в заголовке Authorization: Bearer ....
  5. Dependency декодирует и проверяет подпись JWT.
  6. Protected endpoint получает текущего пользователя или возвращает 401.

Endpoint-ы для проверки

POST /api/auth/registerСоздание пользователя и выдача token-а.
POST /api/auth/loginПроверка пароля и выдача token-а.
GET /api/protectedEndpoint, доступный только с валидным Bearer token.

Ключевой фрагмент

{% raw %}def get_current_user(token: str = Depends(oauth2_scheme)) -> dict:
    payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    username = payload.get("sub")
    user = USERS.get(str(username))
    if user is None:
        raise HTTPException(status_code=401, detail="User not found")
    return user{% endraw %}

Если совсем по-простому

Пользователь доказывает, кто он, через логин и пароль. После этого сервер выдаёт token.

Token похож на пропуск: клиент показывает его при каждом защищённом запросе.

Сервер проверяет подпись token-а и понимает, можно ли доверять данным внутри него.

Построчный разбор

def get_current_user(...)
Dependency, которая пытается найти пользователя по Bearer token.
token: str = Depends(oauth2_scheme)
FastAPI достаёт token из заголовка Authorization.
jwt.decode(...)
Проверяем подпись JWT и читаем payload.

Секрет, которым token подписывался. Без него нельзя проверить подлинность.

Явно разрешаем алгоритм подписи, чтобы не принимать что попало.

Берём subject token-а. В примере это username.
USERS.get(...)
Ищем пользователя в demo-хранилище.
if user is None
Если token указывает на несуществующего пользователя, возвращаем 401.
return user
Если всё хорошо, endpoint получит готовый объект пользователя.

Что здесь важно

  • Token не шифруется, а подписывается: содержимое можно прочитать, но нельзя незаметно изменить без secret key.
  • В demo пользователи хранятся в памяти, поэтому после перезапуска они пропадают.
  • Для role-based доступа добавьте отдельную dependency, которая проверяет user['role'].

Типичные ошибки новичков

  • Хранить пароль в открытом виде вместо hash.
  • Доверять username, который прислал клиент, вместо username из token-а.
  • Путать 401 и 403: 401 - не вошёл, 403 - вошёл, но прав не хватает.

Практическая задача

Добавьте endpoint GET /api/admin, доступный только пользователю с ролью admin.

Сначала выполните задачу самостоятельно, затем откройте вкладку “Ответы” и сравните не только код, но и причину такого решения.

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что меняем

Admin endpoint должен состоять из отдельной dependency проверки роли и самого endpoint-а. Для demo также нужен способ создать admin-пользователя.

  • Добавить dependency require_admin.
  • Добавить endpoint GET /api/admin.
  • Для учебной проверки можно назначать role admin пользователю с username admin.

2. Полный код проверки admin-роли

{% raw %}def require_admin(user: dict = Depends(get_current_user)) -> dict:
    if user["role"] != "admin":
        raise HTTPException(status_code=403, detail="Admin role required")
    return user


@app.get("/api/admin")
async def admin_area(user: dict = Depends(require_admin)):
    return {
        "message": "Это admin endpoint",
        "username": user["username"],
        "role": user["role"],
    }{% endraw %}

3. Как выдать admin-роль в учебном примере

{% raw %}role = "admin" if request.username == "admin" else "user"
USERS[request.username] = {
    "username": request.username,
    "email": request.email,
    "password_hash": pwd_context.hash(request.password),
    "role": role,
}
token, expires = create_access_token(request.username, role){% endraw %}

4. Как проверить

POST /api/auth/registerСоздайте пользователя admin, получите token.
GET /api/adminС admin token вернётся 200.
GET /api/adminС token обычного пользователя вернётся 403.

Короткая версия решения

    if user["role"] != "admin":
        raise HTTPException(status_code=403, detail="Admin role required")
    return user


@app.get("/api/admin")
async def admin(user: dict = Depends(require_admin)):

Разбор решения

  • 401 означает, что пользователь не аутентифицирован; 403 - пользователь известен, но прав не хватает.
  • Проверку роли лучше вынести в dependency, чтобы переиспользовать в нескольких endpoint-ах.
