Глава 9: WebSockets

Постоянное двустороннее соединение, connection manager, receive loop и broadcast.

Порт: 8009 Swagger: http://localhost:8009/docs Результат: После главы вы умеете принять WebSocket-соединение, хранить клиентов и рассылать сообщения всем участникам.

Что разбираем в этой главе

  • WebSocket - протокол для постоянного двустороннего обмена.
  • accept() - явное принятие соединения сервером.
  • receive_text() - ожидание следующего сообщения клиента.
  • WebSocketDisconnect - штатное отключение клиента.
  • ConnectionManager - объект, который хранит активные подключения.

Как проходит запрос

  1. Клиент подключается к ws://localhost:8009/ws.
  2. Сервер вызывает websocket.accept() и создаёт connection id.
  3. Подключение сохраняется в словаре активных клиентов.
  4. Сервер входит в бесконечный цикл приема сообщений.
  5. Каждое сообщение рассылается всем текущим клиентам.
  6. При отключении connection id удаляется из manager-а.

Endpoint-ы для проверки

GET /api/websocket/infoПоказывает endpoint и количество подключений.
WS /wsПростой broadcast-чат.

Ключевой фрагмент

{% raw %}@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    connection_id = await manager.connect(websocket)
    try:
        while True:
            message = await websocket.receive_text()
            await manager.broadcast({
                "event": "message",
                "connection_id": connection_id,
                "message": message,
            })
    except WebSocketDisconnect:
        manager.disconnect(connection_id){% endraw %}

Если совсем по-простому

Обычный HTTP-запрос короткий: клиент спросил, сервер ответил, соединение закончилось.

WebSocket остаётся открытым. Клиент и сервер могут обмениваться сообщениями много раз.

Для чата серверу нужно помнить, кто сейчас подключён.

Построчный разбор

@app.websocket("/ws")
Регистрируем не HTTP endpoint, а WebSocket endpoint.
websocket: WebSocket
Объект активного соединения. Через него принимаем и отправляем сообщения.
await manager.connect(websocket)
Принимаем соединение и сохраняем его в manager-е.
try:
Начинаем блок, где соединение считается открытым.
while True:
Бесконечный цикл. Он работает, пока клиент не отключится.
await websocket.receive_text()
Ждём следующее текстовое сообщение клиента.
await manager.broadcast(...)
Рассылаем сообщение всем подключённым клиентам.
except WebSocketDisconnect:
Если клиент закрыл вкладку или соединение оборвалось, попадаем сюда.
manager.disconnect(connection_id)
Удаляем клиента из списка активных подключений.

Что здесь важно

  • WebSocket endpoint не возвращает HTTP response, он живёт пока открыто соединение.
  • Broadcast должен учитывать отключившихся клиентов, иначе отправка может падать.
  • Для масштабирования на несколько процессов нужен внешний broker, например Redis Pub/Sub.

Типичные ошибки новичков

  • Забыть await websocket.accept() внутри connect.
  • Не удалить отключившегося клиента из manager-а.
  • Думать, что WebSocket endpoint можно проверить обычным curl как HTTP.

Практическая задача

Добавьте команду /who, которая отправляет текущему клиенту количество активных подключений.

Сначала выполните задачу самостоятельно, затем откройте вкладку “Ответы” и сравните не только код, но и причину такого решения.

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что меняем

Команда /who должна обрабатываться внутри receive loop до broadcast. Это команда только для отправителя.

  • Внутри цикла получить текст сообщения.
  • Проверить, равно ли сообщение /who.
  • Если да, отправить ответ только текущему WebSocket.
  • Если нет, оставить обычный broadcast.

2. Полный receive loop после изменения

{% raw %}@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    connection_id = await manager.connect(websocket)
    try:
        while True:
            message = await websocket.receive_text()

            if message == "/who":
                await websocket.send_json({
                    "event": "connections",
                    "count": len(manager.active_connections),
                })
                continue

            await manager.broadcast({
                "event": "message",
                "connection_id": connection_id,
                "message": message,
            })
    except WebSocketDisconnect:
        manager.disconnect(connection_id)
        await manager.broadcast({"event": "disconnected", "connection_id": connection_id}){% endraw %}

3. Как проверить

WS /wsОтправьте /who и получите count только в текущем клиенте.
WS /wsОтправьте обычный текст и получите broadcast у всех клиентов.

Короткая версия решения

{% raw %}if message == "/who":
    await websocket.send_json({
        "event": "connections",
        "count": len(manager.active_connections),
    })
else:
    await manager.broadcast(...){% endraw %}

Разбор решения

  • Команды, предназначенные только отправителю, не нужно рассылать через broadcast.
  • Так появляется первая серверная логика поверх обычного транспорта.
