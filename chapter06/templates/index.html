Глава 6: SQLAlchemy, DTO и SQLite

Engine, Session, ORM-модель, Pydantic DTO, CRUD endpoint-ы и минимальная Alembic-миграция.

Порт: 8006 Swagger: http://localhost:8006/docs Результат: После главы вы умеете связать FastAPI с SQLite и отделять публичные DTO от внутренних ORM-классов.

Что разбираем в этой главе

  • Engine - подключение SQLAlchemy к базе данных.
  • Session - unit of work: через неё читаем, добавляем, изменяем и удаляем строки.
  • DeclarativeBase - база для ORM-классов.
  • Mapped / mapped_column - типизированное описание колонок SQLAlchemy 2.
  • DTO - Pydantic-модели для входного и выходного JSON.
  • Alembic - инструмент миграций схемы БД.

Как проходит запрос

  1. При старте приложения создаётся engine и sessionmaker.
  2. Dependency get_db открывает Session на время запроса.
  3. Endpoint получает Session через Depends.
  4. ORM-модель Product описывает таблицу products.
  5. Pydantic DTO проверяет входные данные и форматирует выходной JSON.
  6. После commit SQLAlchemy записывает изменения в SQLite.

Если совсем по-простому

База данных хранит данные дольше, чем живёт один запрос. SQLAlchemy помогает работать с таблицами как с Python-объектами.

Session - это рабочая область для операций с БД. Через неё мы добавляем, читаем, сохраняем и удаляем данные.

DTO нужны, чтобы внешний JSON API не зависел напрямую от внутренней ORM-модели.

Построчный разбор

def get_db()
Dependency-функция, которая выдаёт подключение к БД на время запроса.
db = SessionLocal()
Создаём новую Session. Через неё endpoint будет работать с БД.
try:
Начинаем блок, где Session отдаётся endpoint-у.
yield db
Отдаём Session наружу. После завершения запроса выполнение вернётся сюда.
finally:
Этот блок выполнится даже если в endpoint-е случилась ошибка.
db.close()
Закрываем Session, чтобы не держать ресурсы.
response_model=ProductDto
FastAPI отдаст наружу только поля, описанные в DTO.
Product(**request.model_dump())
Берём проверенные поля из DTO и создаём ORM-объект.
db.add(product)
Говорим Session: этот объект нужно вставить в таблицу.
db.commit()
Фактически сохраняем изменения в базе.
db.refresh(product)
Обновляем объект, чтобы получить id, выданный базой.

Что здесь важно

  • yield dependency гарантирует закрытие Session после запроса.
  • response_model не отдаёт наружу лишние ORM-поля.
  • В учебном режиме таблицы создаются автоматически, а Alembic показан как правильный путь для реального проекта.

Типичные ошибки новичков

  • Создать объект, но забыть db.commit(): данные не сохранятся.
  • Вернуть ORM-модель без DTO и случайно раскрыть лишние поля.
  • Держать одну Session глобально на всё приложение.

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./chapter06.db")


def make_engine(database_url: str):
    connect_args = {"check_same_thread": False} if database_url.startswith("sqlite") else {}
    kwargs = {"connect_args": connect_args}
    if database_url == "sqlite://":
        kwargs["poolclass"] = StaticPool
    return create_engine(database_url, **kwargs)


engine = make_engine(DATABASE_URL)
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)


class Base(DeclarativeBase):
    pass


app = FastAPI(

class Product(Base):
    __tablename__ = "products"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, index=True)
    name: Mapped[str] = mapped_column(String(120), nullable=False)
    category: Mapped[str] = mapped_column(String(80), default="general")
    description: Mapped[str] = mapped_column(String(500), default="")
    price: Mapped[Decimal] = mapped_column(Numeric(10, 2), nullable=False)
    stock: Mapped[int] = mapped_column(Integer, default=0)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)

    category: str
    description: str

import sqlalchemy as sa


revision = "0002_add_product_category"

4. Как проверить

POST /api/productsBody содержит "category": "books".
GET /api/productsКаждый продукт возвращает поле category.

Полный разбор ответа

Ниже решение разобрано по частям: что стоит на своём месте, зачем это нужно и какие ошибки чаще всего появляются, если часть кода пропустить.

Где появляется новое поле category

Поле категории должно пройти через все слои: ORM-модель, Pydantic DTO, create/update schemas, CRUD endpoint-ы и миграцию.

  • Product.category добавляет колонку на уровне SQLAlchemy ORM.
  • ProductCreate.category разрешает клиенту передать категорию при создании продукта.
  • ProductUpdate.category разрешает поменять категорию при обновлении.
  • ProductDto.category возвращает категорию наружу в JSON-ответе.
  • Если забыть DTO, поле будет в базе, но клиент его не увидит.

Почему нужен default и nullable

  • default="general" даёт понятное значение, если клиент не передал категорию.
  • nullable=False говорит базе: у продукта всегда должна быть категория.
  • В учебной SQLite-БД таблицы создаются автоматически, но в реальном проекте структура меняется через миграции.
  • Если в уже существующей таблице есть старые продукты, миграция должна дать им значение по умолчанию.

Зачем нужна Alembic migration

  • upgrade() описывает движение вперёд: добавить колонку category.
  • downgrade() описывает откат: удалить колонку, если миграцию нужно отменить.
  • Миграция нужна не FastAPI, а базе данных. FastAPI сам не меняет production-схему при каждом запуске.
  • Даже если demo-приложение вызывает create_all, главе важно показать правильный промышленный путь.

Что проверять после изменения

  • Создайте продукт без category. В ответе должно быть category: "general" или выбранное вами значение по умолчанию.
  • Создайте продукт с category: "books". Ответ должен вернуть именно books.
  • Откройте список продуктов. Категория должна быть у каждого объекта.
  • Запустите тесты CRUD с тестовой БД, чтобы убедиться, что изменения не завязаны на локальный файл SQLite.

Читаем DB-ответ сверху вниз

  • Imports SQLAlchemy нужны для engine, session, base class, колонок и типов колонок.
  • DATABASE_URL задаёт адрес базы. По умолчанию используется SQLite-файл главы.
  • engine знает, как подключаться к базе, а SessionLocal создаёт sessions для операций.
  • Base - родитель для ORM-моделей. Через него SQLAlchemy знает, какие таблицы существуют.
  • Product описывает таблицу, а ProductCreate, ProductUpdate, ProductDto описывают JSON снаружи.
  • Endpoint-ы не должны напрямую знать все детали таблицы. Они работают через session и модели.

Почему category проходит через несколько классов

  • ORM-модель отвечает за хранение в базе: без Product.category колонка не появится в таблице.
  • Create schema отвечает за входные данные при создании: без ProductCreate.category клиент не сможет прислать категорию.
  • Update schema отвечает за частичное изменение: без ProductUpdate.category категорию нельзя будет обновить.
  • DTO отвечает за выходной JSON: без ProductDto.category клиент не увидит категорию в ответе.
  • Migration отвечает за реальную схему уже существующей базы: без Alembic production-база не узнает про новую колонку.

Что происходит при создании продукта

  • Клиент отправляет POST /api/products с JSON body.
  • FastAPI валидирует body через ProductCreate.
  • Endpoint создаёт ORM-объект Product(**request.model_dump()) или аналогичную конструкцию.
  • SQLAlchemy session добавляет объект через db.add.
  • db.commit() сохраняет строку в SQLite.
  • db.refresh(product) подтягивает id и значения по умолчанию из базы.
  • FastAPI возвращает объект через ProductDto, и в JSON появляется category.

Короткое резюме решения

  • Менять нужно и ORM-модель, и DTO, иначе поле либо не сохранится, либо не попадёт в публичный ответ.
  • В миграции используйте op.add_column, а в downgrade - op.drop_column.
