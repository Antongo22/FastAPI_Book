Глава 11: Авторизация WebSockets

JWT в query string, проверка до accept(), close code 1008 и сообщения с username.

Порт: 8011 Swagger: http://localhost:8011/docs Результат: После главы вы умеете закрывать WebSocket до принятия соединения, если клиент не прислал валидный token.

Что разбираем в этой главе

  • access_token query - практичный способ передать token из браузерного WebSocket-клиента.
  • verify before accept - сервер проверяет token до websocket.accept().
  • 1008 Policy Violation - WebSocket close code для нарушения политики доступа.
  • JWT claims - username и роль можно брать из подписанного token-а.
  • Authorized broadcast - каждое сообщение содержит подтверждённого пользователя.

Как проходит запрос

  1. Клиент получает access token через /api/auth/login.
  2. Клиент открывает /ws/authorized?access_token=....
  3. Сервер декодирует JWT и проверяет подпись и срок действия.
  4. Если token плохой, сервер закрывает соединение кодом 1008.
  5. Если token валиден, сервер принимает WebSocket и отправляет событие connected.
  6. Сообщения в broadcast получают username из token-а, а не из клиентского текста.

Endpoint-ы для проверки

POST /api/auth/loginДемо-выдача access token-а.
WS /ws/authorized?access_token=...Защищённый WebSocket-чат.

Ключевой фрагмент

{% raw %}@app.websocket("/ws/authorized")
async def authorized_socket(websocket: WebSocket, access_token: str | None = Query(default=None)):
    if not access_token:
        await websocket.close(code=1008)
        return
    try:
        username = verify_token(access_token)
    except HTTPException:
        await websocket.close(code=1008)
        return{% endraw %}

Если совсем по-простому

WebSocket тоже нужно защищать. Иначе любой сможет подключиться к чату.

Перед accept() сервер проверяет token. Если token плохой, соединение закрывается.

Username берётся из JWT, чтобы клиент не мог притвориться другим человеком.

Построчный разбор

@app.websocket("/ws/authorized")
Регистрируем защищённый WebSocket endpoint.
access_token: str | None = Query(default=None)
Читаем token из query string. Он может отсутствовать, поэтому тип включает None.
if not access_token:
Если token не передали, подключение нельзя принимать.
await websocket.close(code=1008)
Закрываем соединение кодом 'нарушение политики'.
return
Останавливаем функцию, чтобы дальше код не выполнялся.
try:
Пробуем проверить token.
username = verify_token(access_token)
Если token валиден, получаем username.
except HTTPException:
Если проверка token-а упала, закрываем WebSocket.
await manager.connect(...)
Только после успешной проверки принимаем соединение.

Что здесь важно

  • Важно проверять token до accept(), чтобы не считать соединение авторизованным даже на короткое время.
  • Клиенту нельзя доверять username из сообщения: он должен быть взят из JWT.
  • В production query token может попасть в логи, поэтому часто применяют короткий срок жизни и HTTPS.

Типичные ошибки новичков

  • Сначала вызвать accept(), а потом проверять token.
  • Брать username из сообщения клиента вместо token-а.
  • Не закрывать соединение явным кодом, из-за чего клиенту труднее понять причину отказа.

Практическая задача

Добавьте claim role в token и запретите подключение к admin-комнате всем, кроме admin.

Сначала выполните задачу самостоятельно, затем откройте вкладку “Ответы” и сравните не только код, но и причину такого решения.

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что меняем

Нужно добавить роль в JWT и проверить эту роль перед подключением к admin-комнате.

  • Добавить claim role при создании access token-а.
  • Вернуть из verify_token username и role.
  • В WebSocket endpoint принять параметр room.
  • Если room == 'admin' и role не admin, закрыть соединение кодом 1008.

2. Полный код token payload и проверки комнаты

{% raw %}def create_access_token(username: str, role: str = "user") -> str:
    expires = datetime.now(timezone.utc) + timedelta(minutes=30)
    return jwt.encode({"sub": username, "role": role, "exp": expires}, SECRET_KEY, algorithm=ALGORITHM)


def verify_token(token: str) -> dict:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        return {"username": str(payload["sub"]), "role": str(payload.get("role", "user"))}
    except (JWTError, KeyError) as error:
        raise HTTPException(status_code=401, detail="Invalid token") from error


@app.websocket("/ws/authorized")
async def authorized_socket(
    websocket: WebSocket,
    access_token: str | None = Query(default=None),
    room: str = "general",
):
    if not access_token:
        await websocket.close(code=1008)
        return
    try:
        user = verify_token(access_token)
    except HTTPException:
        await websocket.close(code=1008)
        return
    if room == "admin" and user["role"] != "admin":
        await websocket.close(code=1008)
        return{% endraw %}

3. Как проверить

WS /ws/authorized?access_token=...&room=generalОбычный пользователь подключается.
WS /ws/authorized?access_token=...&room=adminОбычный пользователь получает close 1008.
WS /ws/authorized?access_token=ADMIN_TOKEN&room=adminAdmin подключается.

Разбор решения

  • Authorization для WebSocket - это не только проверка token-а, но и проверка доступа к конкретной комнате или действию.
  • Для сложных правил лучше вынести проверку в отдельную функцию.
