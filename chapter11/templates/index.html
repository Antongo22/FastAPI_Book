Глава 11: Авторизация Socket.IO

JWT в Socket.IO auth payload, отказ в connect и события от подтверждённого пользователя.

Порт: 8011 Swagger: http://localhost:8011/docs Результат: После главы вы умеете принимать Socket.IO-подключение только с валидным JWT и не доверять username из клиента.

Как пользоваться этой главой

Socket.IO-соединения тоже нужно защищать. Иначе любой клиент сможет подключиться напрямую, минуя обычный login.

Порядок важен: token проверяется в событии connect, до обработки любых пользовательских событий.

Username берётся из JWT, а не из payload события. Это защищает от ситуации, где клиент просто пишет чужое имя.

Если вы только начинаете: не перепрыгивайте сразу к ответу. Сначала запустите пример, затем откройте код рядом с этой страницей и проговаривайте каждую строку обычными словами.

Что разбираем в этой главе

  • Socket.IO auth - объект, который клиент передаёт при подключении: { access_token: token }.
  • connect event - место, где сервер решает принять или отклонить подключение.
  • return False - способ отказать Socket.IO-клиенту при невалидном token-е.
  • JWT claims - username и роль можно брать из подписанного token-а.
  • Authorized event - каждое сообщение содержит пользователя, которого подтвердил сервер.

Как проходит запрос

  1. Клиент получает access token через /api/auth/login.
  2. Клиент подключается к Socket.IO endpoint-у /socket.io и передаёт token в auth.
  3. Сервер декодирует JWT и проверяет подпись и срок действия.
  4. Если token плохой, обработчик connect возвращает False, и Socket.IO отказывает клиенту.
  5. Если token валиден, сервер сохраняет sid -> username и отправляет событие authorized.
  6. Событие authorized_message берёт username из серверного словаря, а не из клиентского payload.

Ключевой фрагмент

{% raw %}def authorize_socketio(auth: dict | None) -> str | None:
    token = (auth or {}).get("access_token") or (auth or {}).get("token")
    if not token:
        return None
    try:
        return verify_token(str(token))
    except HTTPException:
        return None


@sio.event
async def connect(sid, environ, auth):
    username = authorize_socketio(auth)
    if username is None:
        return False
    authorized_clients[sid] = username
    await sio.emit("authorized", {"sid": sid, "username": username}, to=sid){% endraw %}

Если совсем по-простому

Socket.IO-подключение тоже нужно защищать. Иначе любой клиент сможет отправлять события в чат.

Token передаётся при подключении в объекте auth. Сервер проверяет token прямо в событии connect.

Username берётся из JWT и хранится на сервере по sid, чтобы клиент не мог притвориться другим пользователем.

Построчный разбор

Отказываем клиенту в подключении, если token отсутствует или невалиден.

Запоминаем, какой подтверждённый пользователь стоит за этим подключением.

Отправляем подтверждение только текущему клиенту.

Что здесь важно

  • Важно проверять token в connect, до обработки любых пользовательских событий.
  • Клиенту нельзя доверять username из сообщения: он должен быть взят из JWT.
  • Token передаётся в Socket.IO auth payload, а не в query string raw WebSocket URL.

Типичные ошибки новичков

  • Передавать token в query string raw WebSocket URL, хотя в этой главе используется Socket.IO auth payload.
  • Брать username из события клиента вместо JWT.
  • Проверять token только на первом HTTP login, но не проверять его при real-time подключении.

Полное решение задачи

Это ответ именно к задаче из вкладки “Практика”. Здесь показано, что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что меняем

Нужно добавить роль в JWT и проверять её в Socket.IO событии, которое доступно только admin.

  • Добавить claim role при создании access token-а.
  • Вернуть из helper-а проверки token-а username и role.
  • Сохранить данные пользователя в словаре authorized_clients при Socket.IO connect.
  • Добавить событие admin_message.
  • Если роль текущего sid не admin, отправить событие forbidden только этому клиенту.

2. Полный код token payload и admin-события

{% raw %}def create_access_token(username: str, role: str = "user") -> str:
    expires = datetime.now(timezone.utc) + timedelta(minutes=30)
    return jwt.encode({"sub": username, "role": role, "exp": expires}, SECRET_KEY, algorithm=ALGORITHM)


def verify_user_token(token: str) -> dict:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        return {"username": str(payload["sub"]), "role": str(payload.get("role", "user"))}
    except (JWTError, KeyError) as error:
        raise HTTPException(status_code=401, detail="Invalid token") from error


@sio.event
async def admin_message(sid, data):
    user = authorized_clients.get(sid)
    if user is None or user["role"] != "admin":
        await sio.emit("forbidden", {"reason": "admin role required"}, to=sid)
        return
    await sio.emit("admin_message", {
        "from": user["username"],
        "message": data.get("message", ""),
    }, room="admins"){% endraw %}

3. Как проверить

Socket.IO connectОбычный пользователь подключается с auth: { access_token }.
Socket.IO admin_messageОбычный пользователь получает событие forbidden.
Socket.IO admin_messageAdmin получает событие admin_message.

Разбор решения

  • Authorization для Socket.IO - это не только проверка token-а при connect, но и проверка доступа к конкретному событию.
  • Для сложных правил лучше вынести проверку в отдельную функцию.
