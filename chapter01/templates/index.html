Глава 1: Начало работы с FastAPI

Создание приложения, middleware, REST API, Pydantic-модели и автоматическая OpenAPI-документация.

Порт: 8001 Swagger: http://localhost:8001/docs Результат: После главы вы понимаете путь HTTP-запроса от браузера до endpoint-функции и умеете собрать простой API.

Что разбираем в этой главе

  • FastAPI app - объект приложения, который хранит маршруты, middleware и настройки документации.
  • Path operation - функция с декоратором @app.get, @app.post и так далее.
  • Pydantic model - контракт входного JSON: типы, обязательные поля и автоматическая валидация.
  • Middleware - код вокруг каждого запроса. Он может логировать, добавлять заголовки или измерять время.
  • OpenAPI - схема API, из которой FastAPI строит Swagger UI на /docs.

Как проходит запрос

  1. Клиент отправляет POST /api/calculator/add с JSON-телом.
  2. FastAPI выбирает endpoint по методу и пути.
  3. Pydantic проверяет, что в теле есть числа a и b.
  4. Endpoint получает уже разобранный объект CalculationRequest.
  5. Middleware добавляет заголовок X-FastAPI-Book-Chapter в ответ.
  6. FastAPI сериализует словарь Python в JSON и возвращает HTTP 200.

Endpoint-ы для проверки

POST /api/calculator/addСложение двух чисел.
POST /api/calculator/subtractВычитание второго числа из первого.

Ключевой фрагмент

{% raw %}class CalculationRequest(BaseModel):
    a: float
    b: float


@app.post("/api/calculator/divide")
async def divide(request: CalculationRequest):
    if request.b == 0:
        raise HTTPException(status_code=400, detail="Деление на ноль невозможно")
    return {"result": request.a / request.b, "operation": "divide"}{% endraw %}

Если совсем по-простому

Код в этой главе делает маленький калькулятор. Пользователь отправляет два числа, сервер считает результат и возвращает JSON.

Главная идея: FastAPI сам читает JSON, сам проверяет типы, сам вызывает нужную функцию и сам превращает словарь Python в HTTP-ответ.

Если вы только начинаете Python: двоеточие : открывает блок кода, а отступы показывают, какие строки относятся к классу, функции или условию.

Построчный разбор

class CalculationRequest(BaseModel):
Создаём класс-описание входных данных. Это не обычный калькулятор, а схема: какие поля пользователь должен прислать в JSON.
BaseModel
Базовый класс Pydantic. Благодаря ему FastAPI понимает, что нужно проверить тело запроса.
a: float
Поле a обязательно. float значит число с дробной частью или без неё: 10, 10.5, 0.
b: float
Второе обязательное число. Если пользователь пришлёт строку, которую нельзя превратить в число, FastAPI вернёт ошибку валидации.
@app.post("/api/calculator/divide")
Декоратор. Он говорит FastAPI: когда придёт POST-запрос на этот адрес, вызови функцию ниже.
async def divide(...):
Объявляем асинхронную функцию endpoint-а. async нужно, чтобы FastAPI мог эффективно обслуживать много запросов.
request: CalculationRequest
Параметр функции. FastAPI создаст объект CalculationRequest из JSON-тела запроса и положит его в переменную request.
if request.b == 0:
Обычная проверка Python: если второе число равно нулю, делить нельзя.
raise HTTPException(...)
Останавливаем выполнение функции и возвращаем клиенту ошибку HTTP 400. Это лучше, чем дать Python упасть с делением на ноль.
return {"result": ...}
Возвращаем словарь. FastAPI сам превратит его в JSON-ответ.

Что здесь важно

  • BaseModel говорит FastAPI читать тело запроса как JSON.
  • Если поле отсутствует или тип не подходит, endpoint даже не будет вызван: FastAPI вернет validation error.
  • HTTPException используется для ожидаемых бизнес-ошибок, где вы сами выбираете status code.

Типичные ошибки новичков

  • Забыть двоеточие после class, def или if.
  • Сделать неправильный отступ: в Python отступы заменяют фигурные скобки.
  • Написать request["b"] вместо request.b. Pydantic-модель здесь используется как объект с полями.
  • Не проверить деление на ноль и получить внутреннюю ошибку сервера вместо понятного ответа 400.

Откройте Swagger UI, найдите endpoint-ы этой главы, нажмите Try it out и выполните запросы с разными входными данными. После этого вернитесь в код и сопоставьте каждый ответ с тем участком, который его формирует.

Практическая задача

Добавьте endpoint POST /api/calculator/power, который возводит a в степень b. Он должен возвращать тот же формат ответа: result и operation.

Сначала выполните задачу самостоятельно, затем откройте вкладку “Ответы” и сравните не только код, но и причину такого решения.

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что меняем

Задача просит добавить новую операцию калькулятора. Никакие новые модели не нужны: входные данные такие же, как у add/subtract/multiply/divide.

  • Открыть файл chapter01/app/main.py.
  • Найти блок endpoint-ов калькулятора.
  • Добавить новый endpoint рядом с остальными операциями.
  • Проверить через Swagger, что endpoint появился в группе calculator.

2. Полный фрагмент калькулятора после изменения

Ниже не одна функция, а весь логический блок калькулятора. Так проще увидеть, что новая операция использует тот же request model и тот же стиль ответа.

{% raw %}class CalculationRequest(BaseModel):
    a: float
    b: float


@app.post("/api/calculator/add")
async def add(request: CalculationRequest):
    return {"result": request.a + request.b, "operation": "add"}


@app.post("/api/calculator/subtract")
async def subtract(request: CalculationRequest):
    return {"result": request.a - request.b, "operation": "subtract"}


@app.post("/api/calculator/multiply")
async def multiply(request: CalculationRequest):
    return {"result": request.a * request.b, "operation": "multiply"}


@app.post("/api/calculator/divide")
async def divide(request: CalculationRequest):
    if request.b == 0:
        raise HTTPException(status_code=400, detail="Деление на ноль невозможно")
    return {"result": request.a / request.b, "operation": "divide"}


@app.post("/api/calculator/power")
async def power(request: CalculationRequest):
    return {"result": request.a ** request.b, "operation": "power"}{% endraw %}

Запустите главу и выполните запросы через Swagger или curl.

POST /api/calculator/powerBody: {"a": 5, "b": 0} → {"result": 1, "operation": "power"}

Разбор решения

  • Новая операция использует уже существующую модель, потому что входной контракт такой же.
  • Swagger UI автоматически покажет новый endpoint после перезапуска приложения.
