Глава 12: Тестирование

TestClient, dependency overrides, in-memory SQLite, service layer и интеграционные сценарии.

Порт: 8012 Swagger: http://localhost:8012/docs Результат: После главы вы умеете тестировать FastAPI endpoint-ы без реальной БД и проверять бизнес-логику отдельно от HTTP.

Что разбираем в этой главе

  • TestClient - синхронный клиент для тестирования ASGI-приложения.
  • dependency_overrides - замена production dependency тестовой реализацией.
  • sqlite:// + StaticPool - одна in-memory БД на весь тестовый engine.
  • Service layer - класс ChatService, который можно проверять отдельно.
  • Integration test - запрос проходит через routing, validation, dependency и БД.

Как проходит запрос

  1. Тест создаёт in-memory SQLite engine.
  2. Таблицы создаются через Base.metadata.create_all.
  3. Production dependency get_db заменяется тестовой.
  4. TestClient вызывает реальные HTTP endpoint-ы приложения.
  5. Endpoint использует тестовую Session и не трогает файл на диске.
  6. После теста overrides очищаются, чтобы не повлиять на другие тесты.

Endpoint-ы для проверки

GET /api/chat/groupsСписок групп.

Если совсем по-простому

Тесты нужны, чтобы изменения не ломали уже работающий код.

FastAPI позволяет запускать endpoint-ы в тестах без настоящего веб-сервера.

Dependency override позволяет подменить настоящую БД тестовой in-memory БД.

Построчный разбор

app.dependency_overrides[get_db] = override
Говорим FastAPI: когда endpoint попросит get_db, используй тестовую функцию.
try:
Начинаем блок теста, после которого обязательно очистим override.
client = TestClient(app)
Создаём тестовый клиент. Он вызывает приложение как будто по HTTP.
client.post(...)
Отправляем POST-запрос в приложение.
json={...}
Тело запроса. TestClient сам превратит словарь в JSON.
group["id"]
Берём id созданной группы из ответа, чтобы использовать его в следующем запросе.
finally:
Этот блок выполнится даже если assert упал.
app.dependency_overrides.clear()
Очищаем подмены зависимостей, чтобы следующий тест был независимым.

Что здесь важно

  • Override делает тест изолированным: он не зависит от локальных SQLite-файлов.
  • Проверяйте не только status code, но и важные поля JSON-ответа.
  • Для WebSocket есть отдельный websocket_connect в TestClient.

Типичные ошибки новичков

  • Не очищать dependency overrides после теста.
  • Тестировать на реальной локальной БД и получать нестабильные результаты.
  • Проверять только status code и не проверять важные поля ответа.

Практическая задача

Добавьте endpoint удаления группы и тест, что сообщение удалённой группы больше не возвращается.

Сначала выполните задачу самостоятельно, затем откройте вкладку “Ответы” и сравните не только код, но и причину такого решения.

Полное решение задачи

Здесь решение показано как в большом учебнике: что менять, какой код вставлять, где он должен находиться и как проверить результат. Это не только одна функция, а весь минимальный контекст, чтобы новичок не гадал, куда вставлять кусок кода.

1. Что меняем

Задача про удаление группы должна быть решена на всех уровнях: service method, endpoint и тест.

  • Добавить метод delete_group в ChatService.
  • Решить, что делать с сообщениями группы. В учебном варианте удаляем их перед удалением группы.
  • Добавить endpoint DELETE /api/chat/groups/{group_id}.
  • Написать тест: создать группу, сообщение, удалить группу, проверить 204 и пустой список сообщений.

2. Полный service method и endpoint

{% raw %}class ChatService:
    def delete_group(self, group_id: int) -> None:
        group = self.db.get(ChatGroup, group_id)
        if group is None:
            raise HTTPException(status_code=404, detail="Group not found")

        self.db.query(Message).filter(Message.group_id == group_id).delete()
        self.db.delete(group)
        self.db.commit()


@app.delete("/api/chat/groups/{group_id}", status_code=204)
async def delete_group(group_id: int, service: ChatService = Depends(get_chat_service)):
    service.delete_group(group_id){% endraw %}

3. Полный тест

{% raw %}def test_delete_group_removes_group_messages():
    _, override = make_sqlite_override(Base, get_db)
    app.dependency_overrides[get_db] = override
    try:
        client = TestClient(app)
        group = client.post("/api/chat/groups", json={"name": "general"}).json()
        client.post("/api/chat/messages", json={
            "text": "hello",
            "sender": "anna",
            "group_id": group["id"],
        })

        response = client.delete(f"/api/chat/groups/{group['id']}")
        assert response.status_code == 204
        assert client.get(f"/api/chat/messages?group_id={group['id']}").json() == []
    finally:
        app.dependency_overrides.clear(){% endraw %}

Разбор решения

  • Сначала напишите тест на ожидаемое поведение, затем реализуйте service method.
  • Решите явно: сообщения удаляются каскадно или получают group_id=None. Для учебного чата проще каскадное удаление.
